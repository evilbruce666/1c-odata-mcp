## read.accounting

### `read.accounting.check_month_close` — Проверка закрытия месяца

Проверка учёта за месяц — то, что бухгалтер смотрит перед сдачей отчётности и после закрытия месяца: (1) закрытие месяца выполнено и без ошибок, закрыты ли предыдущие месяцы года; (2) непроведённые документы месяца; (3) красное сальдо на конец месяца — деньги и товары в минусе, расчёты 62/60 не на той стороне; (4) остатки на 90, 91 (должны быть в нуле) и 20–26, 44 после закрытия и документы, созданные позже операции закрытия (если остатки есть); (5) амортизация при наличии ОС и НМА; (6) реализации с НДС без счёта-фактуры. Каждая проверка — статус ok / warning / error / not_applicable / skipped, пояснение и строки (до 20). Остатки на 90/91/25/26 на начало месяца — признак, что прошлые месяцы закрыты не полностью. closingCreatedAt — когда впервые создана операция закрытия (документы, созданные позже, могли в него не попасть; перезакрытие этого времени не меняет). Для перехода в карточку счёта: analyticsRefs с analyticsTypes Catalog_Контрагенты — counterpartyRef, иначе dimensionRef. У регламентных операций в БП Posted = false — это нормально. Только чтение: закрыть месяц через OData нельзя, только проверить результат.

### `read.accounting.get_account_card` — Карточка счёта

Карточка счёта за период — каждое движение с корреспонденцией: дата, документ, содержание, Дт или Кт, корреспондирующий счёт и его аналитика, остаток после движения; сальдо на начало, обороты, сальдо на конец (сверено с регистром, consistent). account — код или префикс («51», «62.01», «26»). Отбор: counterpartyRef — контрагент (Ref_Key из find_counterparty), dimensionRef — любое другое субконто (договор, номенклатура, банковский счёт, документ расчётов). Сторно приходит отрицательной суммой в debit/credit. documentCreatedAt — когда документ создан (по ссылке): помогает найти документы, внесённые после закрытия месяца. Если остаток сложился до периода — возьмите период шире. Для разбора: откуда остаток на 26, кто дал красное сальдо, как сложился долг. Сальдо и balance: плюс — дебет, минус — кредит. count — строки карточки (проводка внутри счёта даёт две), scan.rowsScanned — проводки. Ответ постраничный: count — всего движений, returned — сколько в этом ответе; при truncated=true читайте дальше с offset=nextOffset и snapshot из прошлого ответа, пока в ответе есть nextOffset; dataChanged — данные изменились, начните заново. За один ответ не больше 100 строк и примерно 45000 символов, что бы ни стояло в limit. Обороты и остатки всегда по всему периоду. Итоги по месяцам, корреспондирующим счетам, контрагентам или договорам (своей или корреспондирующей стороны): groupBy, сумма групп равна оборотам карточки; с summaryOnly=true строк нет и ответ быстрее. Для этого не нужно читать все страницы. balanceTracked=false — отбор по субконто только с оборотами (статья ДДС на 51, статья затрат на 91): сальдо по нему в 1С нет, верны только обороты. Не отдаёт обороты по субсчетам (это get_account_turnover) и не разбирает текст назначений платежей.

### `read.accounting.get_account_turnover` — ОСВ по счёту

Оборотно-сальдовая ведомость по бухгалтерскому счёту (регистр бухгалтерии Хозрасчетный, виртуальная таблица «Остатки и обороты») за период: сальдо на начало Дт/Кт, обороты Дт/Кт, сальдо на конец Дт/Кт — итогом и по субсчетам. account — код счёта или префикс («51», «60», «62», «90.01»): берутся все субсчета, код которых начинается с него. Сальдо развёрнутое по аналитике (измерения и субконто), как в стандартной ОСВ по счёту. Можно ограничить организацией. Период — даты YYYY-MM-DD включительно. Не отбирает по аналитике и не разбивает по месяцам. Оборот по контрагенту, договору или другому субконто, по месяцам или корреспондирующим счетам — read.accounting.get_account_card с counterpartyRef или dimensionRef, groupBy и summaryOnly=true; ссылку договора дают его группы (groupBy: contract). Деньги по статье ДДС — read.analytics.get_payments_breakdown с cashflowItem. Из каких документов сложился остаток — get_balance_origin.

### `read.accounting.get_balance_origin` — Откуда сложилось сальдо

Из каких документов состоит остаток по счёту на дату и с какого времени он висит — для старых хвостов, которых не видно в карточке за месяц. Где учёт ведётся по документам расчётов (62, 60, 76 в БП), состав — из сальдо 1С (method = documents). Иначе — по истории движений (method = movements): момент, с которого остаток держится непрерывно, и доля каждого документа, дожившая до даты; поиск назад до maxYears лет. since — дата самого старого документа остатка, documentCreatedAt — когда документ создан. Отбор: counterpartyRef — контрагент, dimensionRef — договор, номенклатура, банковский счёт. Обороты и сальдо по субсчетам — get_account_turnover, все движения за период — get_account_card.

### `read.analytics.get_cash_balance` — Деньги на счетах и в кассе

| `database` | string |  | Имя базы 1С из list_databases. Без указания — база по умолчанию; если баз несколько и неясно какая, спросите пользователя. |
| `organization` | string |  | Организация (юрлицо) для фильтра: часть названия, ИНН или Ref_Key из list_organizations. Без указания — все организации базы. |
| `warehouse` | string |  | Название, код или Ref_Key склада (если несколько) |
| `inventoryRef` | string |  | Ref_Key инвентаризации-основания (в Управлении торговлей — пересчёта товаров), необязательно |
| `date` | string |  | Дата YYYY-MM-DD (по умолчанию — момент предпросмотра) |
| `lines` | список (объект: nomenclatureRef, quantity, price, seriesRef) | да | Позиции документа |
| `department` | string |  | Управление торговлей: подразделение (аналитика доходов и расходов) — название, код или Ref_Key; без него поле пустое |
| `expenseItem` | string |  | Управление торговлей, обязательно: статья расходов — название, код или Ref_Key. НЕ выбирайте сами — уточните у пользователя |
| `comment` | string |  | Управление торговлей: комментарий документа |
| `confirm` | boolean |  | false (по умолчанию) — только предпросмотр (dry-run), запись НЕ выполняется. true — выполнить создание. Сначала всегда показывайте dry-run и получайте согласие пользователя; при подтверждении передавайте operationId из результата предпросмотра и те же аргументы. После таймаута повторяйте подтверждение с тем же id, не создавая новый предпросмотр.. по умолчанию `false` |
| `operationId` | string |  | UUID из предпросмотра. Передайте его при confirm=true, чтобы повтор не создал дубликат. |
| `responsibleRef` | string |  | Ответственный документа — Ref_Key пользователя 1С (read.catalog.list_users): ставится в «Ответственный» или, где его нет (продажи и закупки УТ), в «Менеджер». Помеченный, недействительный и служебный — отказ; у документов без обоих полей (ПКО, РКО и заявка на расходование УТ) — отказ. Заменяет ответственного из fields |
