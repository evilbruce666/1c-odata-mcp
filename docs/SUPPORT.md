# Поддержка по конфигурациям

Каждый инструмент — в Бухгалтерии предприятия 3.0 и в Управлении торговлей 11: чем подтверждено, что он работает.
Клетка — одно из пяти:

- **вживую (база, дата)** — инструмент вызван на настоящей 1С этой конфигурации, ответ проверен (запись — контрольным
  чтением, проведение — сверкой движений);
- **отказ по замыслу (причина)** — в этой конфигурации такого объекта нет, инструмент отказывает до записи и говорит,
  чем заменить; отказ тоже проверен вживую;
- **исключение (решение владельца, причина)** — инструмент не может сделать это в настоящей 1С из-за самой 1С или
  прав, и владелец принял это как границу поддержки;
- **только подделка (причина)** — проверено только тестами на поддельной 1С со снимком схемы;
- **не сделано** — инструмент в этой конфигурации не работает.

«Полная поддержка» конфигурации — ни одной клетки двух последних видов. Число клеток каждого вида ниже и заполненность
таблиц сверяет `test/support-matrix.test.ts`.

**Базы проверки.** БП 3.0 — две рабочие базы: чтение на обеих; запись на одной — объекты с меткой ZZ-TEST создаются
непроведёнными и помечаются на удаление, проведение — только с отдельного разрешения владельца базы. УТ 11.5 — копия
рабочей базы, пересоздаётся из неё каждые сутки; записи — документы тестовой организации с комментарием ZZ-TEST
(созданы, проведены со сверкой движений, проведение отменено, помечены на удаление) и элементы справочников ZZ-TEST.

**Как повторить:** `npm run test:live:read` (чтение, запись заблокирована), `npm run test:live -- --db <база> --yes`
(все инструменты записи Бухгалтерии; `--no-post` — без проведения), `npm run test:live:ut -- --db <база> --org
<организация> --warehouse <склад> --yes` (склад, деньги, продажи и закупки Управления торговлей с проведением),
`npm run test:live:http` (запись по HTTP); порядок — [TESTING.md](TESTING.md#живая-проверка-на-копии-базы).

## Исключения и границы

**Не проверено вживую** — в базах проверки таких данных нет; код работает по схеме и проверен тестами:

- **Расчёты в валюте и условных единицах.** В трёх базах проверки ни одного такого договора. Чтение и создание
  документов — по схеме; правка суммы денежного документа, выравнивание суммы банковского документа и правка суммы
  в у.е. — отказ, сверка проведения в валюте договора сумму расчётов не сравнивает.
- **Правка суммы многострочного денежного документа в Управлении торговлей** — отказ: сумму по строкам задают при создании (`settlementLines`) или в 1С.
- **Эквайринг в Бухгалтерии без комиссии в строке и по нескольким договорам** — не сделано: на рабочих базах одна строка на договор с банком.
- **Перевод между своими счетами через 57.01** (деньги в пути): на проверенной базе 1С ставит прямой перевод Дт 51
  Кт 51; схема через 57.01 и парное поступление «Перевод с другого счёта» не проверены.
- **Проверки НДС и амортизации в `check_month_close`** — обе базы Бухгалтерии на УСН и без основных средств.
- **Ценообразование 2.5** в установке и чтении цен Управления торговлей — копия на прежнем механизме цен.
- **Ордерные склады Управления торговлей** — на копии их нет; сверка движений склада для них пропускается с заметкой.
- **Порядок приоритетов настроек счетов расчётов** (договор, контрагент, группа) против правил самой 1С при
  конфликтах и вложенных группах.

- **Ордерные склады УТ** — документы создаются и проводятся, но товар и серии на складе 1С двигает ордерами позже: сверка склада
  при проведении пропускается с заметкой, расчёты с партнёром сверяются.
- **Розница УТ** (отчёт о розничных продажах, кассы ККМ, выплата зарплаты) — запись отказывает по замыслу.
- **КА 2 и ERP 2** — вне этого заявления: чтение и справочники по схеме УТ проверены только на поддельной 1С;
  складской документ, устроенный как в УТ, в базе с бухучётом — отказ с причиной.
- **Прочие операции Бухгалтерии** (ПКО «Прочий приход», РКО «Прочий расход», списание «Прочее списание» и
  «Перечисление налога») — с обязательным корреспондирующим счётом `corrAccount`; «Перечисление зарплаты» и
  «Снятие наличных» коннектор не создаёт — на проверенной базе 1С проводила их без проводок; перевод на другой
  счёт — с обязательным счётом-получателем той же организации и валюты, схему перевода выбирает 1С; субконто счёта, которые коннектор не заполняет (например,
  документы расчётов), остаются пустыми с заметкой в предпросмотре.
- **Акт выполненных работ УТ** не проводится в самой конфигурации (ошибка 1С), поэтому услуги продаются реализацией —
  `create_act` в УТ создаёт её.
