# Установка с помощью ИИ-ассистента

Этот документ написан для ИИ-ассистента (ChatGPT, Claude, Gemini, DeepSeek, GigaChat, локальная
модель — любого), которому пользователь дал ссылку на репозиторий и попросил помочь установить
коннектор. Человеку его тоже можно читать: это та же установка, разложенная по шагам.

**Ассистент, вот что нужно знать сразу:**

- **1c-odata-mcp — локальный MCP-сервер.** Он устанавливается на компьютер пользователя, запускается
  его ИИ-приложением командой `npx -y 1c-odata-mcp` и ходит по OData в **его собственную базу 1С**.
  Облачной версии нет, регистрироваться нигде не нужно.
- **От пользователя нужны три вещи:** адрес OData его базы, логин и пароль пользователя 1С. И
  ИИ-приложение, которое умеет запускать локальные MCP-серверы (шаг 1).
- **Устанавливай только в режиме чтения.** Сервер по умолчанию ничего не меняет в 1С — не включай
  запись сам; если пользователь просит её, сначала предупреди о риске (правила 3 и 4 ниже).

Веди пользователя по шагам ниже по порядку и после каждого шага проверяй результат — так сразу видно,
где проблема.

---

## Правила для ассистента

1. **Не проси прислать пароль в чат.** Дай шаблон конфига с `...` вместо пароля — пользователь впишет
   его сам.
2. **Не затирай чужие настройки.** Если в конфиге уже есть другие MCP-серверы, добавь `1c-odata`
   рядом с ними, а не заменяй файл целиком.
3. **Настраивай только чтение.** Конфиги в этом документе — только для чтения, и так их и оставляй:
   не добавляй `READ_ONLY`, `ODATA_WRITABLE`, `ODATA_DB_<ИМЯ>_WRITABLE` и другие переменные записи,
   даже если думаешь, что они пригодятся. Для подключения посоветуй отдельного пользователя 1С с
   правами **только на чтение** — тогда и ошибка в настройке ничего не сможет изменить в базе.
4. **Если пользователь сам просит запись — сначала предупреди о риске,** и только после его явного
   «да» направь в [CONNECTING.md](CONNECTING.md#включение-записи-опционально). Скажи прямо:
   - с записью ИИ сможет создавать, изменять и проводить документы и справочники в **рабочей
     бухгалтерии**; проведённый документ меняет учёт и отчётность, ошибку придётся искать и
     исправлять бухгалтеру;
   - каждая запись идёт через предпросмотр и подтверждение, но подтверждает человек — внимательно
     читайте предпросмотр, а не соглашайтесь по привычке;
   - сначала включите запись на **копии или тестовой базе**, а в рабочей — только с
     резервной копией и отдельным пользователем 1С, у которого права на запись лишь тех
     объектов, что действительно нужны;
   - запись включается отдельно на каждую базу — остальные базы оставьте только на чтение.
5. **Не предлагай выставить сервер в интернет** (туннели, проброс портов, публичный хостинг), чтобы
   подключить его к веб-чату. Через такой сервер наружу уходит доступ к бухгалтерии. Правильный путь —
   приложение на компьютере (шаг 1).
6. **Не придумывай параметры.** Все настройки — в этом документе, в [CONNECTING.md](CONNECTING.md) и
   в [`.env.example`](../.env.example).

## Шаг 1. Где пользователь будет спрашивать 1С

Коннектор работает только в приложениях, которые запускают **локальные** MCP-серверы. Спроси
пользователя, чем он пользуется, и выбери строку:

| Пользователь сейчас в… | Что делать |
|---|---|
| **Claude Desktop** (приложение Claude для Mac/Windows) | Подходит. Конфиг — шаг 4А |
| **ChatGPT в приложении для компьютера** | Подходит через **Codex** (он встроен в приложение) — шаг 4Б. Обычный чат ChatGPT локальные серверы не запускает |
| **Cursor**, **VS Code**, **JetBrains**, **Zed**, **Cline**, **Continue** | Подходит — шаг 4В |
| **LM Studio** (локальная модель, данные не покидают компьютер) | Подходит — шаг 4В |
| **Claude Code**, **Codex CLI** (терминал) | Подходит — шаг 4Г |
| **Веб-чат в браузере**: ChatGPT, Claude.ai, Gemini, DeepSeek, Алиса, GigaChat, Copilot | **Не подойдёт:** веб-чат не может запустить программу на компьютере пользователя. Предложи поставить приложение. Проще всего — **Claude Desktop** (claude.ai/download); если пользователь привык к ChatGPT — **приложение ChatGPT для компьютера** с Codex; если данные не должны уходить во внешний ИИ — **LM Studio** с локальной моделью |

Ты можешь продолжать помогать из веб-чата: давать команды и конфиги, которые пользователь выполнит
сам. Сам коннектор будет работать в приложении, которое он поставит.

## Шаг 2. Node.js 22 или новее

Сервер запускается через `npx`, он входит в Node.js. Попроси выполнить в терминале (на Windows —
PowerShell или «Командная строка»):

```bash
node -v
```

- Ответ `v20…` или выше — всё готово.
- Команда не найдена или версия ниже 20 — установить LTS-версию с [nodejs.org](https://nodejs.org) и
  **перезапустить** терминал и ИИ-приложение.

## Шаг 3. Адрес OData и учётные данные

Это часть, где нужен человек со стороны 1С — бухгалтер, администратор или облачный провайдер.

**Адрес** имеет вид (завершающий слэш обязателен):

```
https://<сервер>/<имя_базы>/odata/standard.odata/
```

- Своя публикация на IIS/Apache: `https://ваш-сервер/<имя_публикации>/odata/standard.odata/`
- Облако (1cFresh, Scloud, аренда 1С): адрес и включение OData — у провайдера, обычно в личном
  кабинете или по заявке. Пример Scloud: `https://terminal.scloud.ru/<кластер>/<имя_базы>/odata/standard.odata/`

**Логин и пароль** — пользователь информационной базы 1С с паролем. На некоторых облачных площадках
нужна учётная запись от личного кабинета площадки, а не пользователь внутри базы.

**Проверка в браузере** — попроси открыть адрес с `?$format=json` на конце и ввести логин и пароль:

| Что видно | Что это значит |
|---|---|
| Снова просит пароль, не пускает (401) | Не та учётная запись — см. выше про облачные площадки |
| Пустил, но `"value": []` | В 1С не настроен «Состав» OData — какие объекты отмечать, в [CONNECTING.md](CONNECTING.md#минимальный-состав-для-этого-сервера-бухгалтерия-30) |
| Пустил, в `value` длинный список | Всё готово, переходи к шагу 4 |
| Страница не открывается, 404 | OData не опубликован — [ODATA-SETUP.md](ODATA-SETUP.md), по вариантам 1С |

Без этой проверки дальше идти бессмысленно: сервер получит те же ошибки.

## Шаг 4. Подключить сервер к приложению

Во всех приложениях запись одна и та же — команда `npx -y 1c-odata-mcp` и три переменные. Меняется
только файл и название раздела.

### 4А. Claude Desktop

Настройки → **Разработчик** (Developer) → **Изменить конфигурацию** (Edit Config). Откроется
`claude_desktop_config.json` (macOS: `~/Library/Application Support/Claude/`, Windows:
`%APPDATA%\Claude\`). Добавить в `mcpServers`:

```json
{
  "mcpServers": {
    "1c-odata": {
      "command": "npx",
      "args": ["-y", "1c-odata-mcp"],
      "env": {
        "ODATA_BASE_URL": "https://<сервер>/<база>/odata/standard.odata/",
        "ODATA_USERNAME": "...",
        "ODATA_PASSWORD": "..."
      }
    }
  }
}
```

Затем **полностью** закрыть Claude Desktop (macOS — Cmd+Q, Windows — выход из значка в трее) и
открыть снова.

### 4Б. ChatGPT в приложении для компьютера (Codex) и Codex CLI

Codex в приложении ChatGPT, Codex CLI и расширение Codex для IDE читают один файл
`~/.codex/config.toml` (Windows: `%USERPROFILE%\.codex\config.toml`). Можно через интерфейс:
Settings → MCP servers → Add server → STDIO. Или дописать в файл:

```toml
[mcp_servers.1c-odata]
command = "npx"
args = ["-y", "1c-odata-mcp"]

[mcp_servers.1c-odata.env]
ODATA_BASE_URL = "https://<сервер>/<база>/odata/standard.odata/"
ODATA_USERNAME = "..."
ODATA_PASSWORD = "..."
```

Или одной командой в терминале:

```bash
codex mcp add 1c-odata --env ODATA_BASE_URL=https://<сервер>/<база>/odata/standard.odata/ --env ODATA_USERNAME=... --env ODATA_PASSWORD=... -- npx -y 1c-odata-mcp
```

Проверка — `codex mcp list`. Перезапустить приложение. Готовых сценариев (MCP prompts) Codex не
показывает — те же вопросы можно задать словами (шаг 5).

### 4В. Другие приложения

Запись та же, что в 4А, отличается место:

| Приложение | Куда вписать | Раздел |
|---|---|---|
| **Cursor** | Settings → MCP, или файл `~/.cursor/mcp.json` | `mcpServers` |
| **VS Code** (Copilot, режим агента) | палитра команд → `MCP: Add Server` → Command (stdio), или `.vscode/mcp.json` | `servers`, у записи добавить `"type": "stdio"` |
| **LM Studio** | вкладка Program → Install → Edit `mcp.json` (`~/.lmstudio/mcp.json`) | `mcpServers` |
| **JetBrains AI Assistant** | Settings → Tools → AI Assistant → Model Context Protocol → Add (или кнопка импорта из Claude Desktop) | `mcpServers` |
| **Zed** | Settings → AI → MCP Servers → Add Local Server, или `settings.json` | `context_servers` |
| **Cline** | значок MCP Servers → Configure → `cline_mcp_settings.json` | `mcpServers` |
| **Continue** | файл в `.continue/mcpServers/` — JSON из 4А подходит как есть; работает в режиме агента | `mcpServers` |
| **Devin Desktop** (бывший Windsurf) | меню «…» в панели Cascade → Open MCP config | `mcpServers` |

Пример для VS Code, где раздел называется иначе:

```json
{
  "servers": {
    "1c-odata": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "1c-odata-mcp"],
      "env": {
        "ODATA_BASE_URL": "https://<сервер>/<база>/odata/standard.odata/",
        "ODATA_USERNAME": "...",
        "ODATA_PASSWORD": "..."
      }
    }
  }
}
```

Приложения нет в списке — ищи в его документации «MCP server» или «Model Context Protocol» и раздел
про **локальные** (stdio) серверы. Почти всегда это та же тройка `command` / `args` / `env`.

### 4Г. Claude Code

```bash
claude mcp add 1c-odata -s user --env ODATA_BASE_URL=https://<сервер>/<база>/odata/standard.odata/ --env ODATA_USERNAME=... --env ODATA_PASSWORD=... -- npx -y 1c-odata-mcp
```

Проверка — `claude mcp list`.

## Шаг 5. Проверить

1. В новом чате приложения попросить: **«проверь соединение с 1С»**. Сервер вызовет
   `read.system.health_check` и вернёт версию OData и число опубликованных объектов.
2. Затем: **«сколько денег сейчас»** или **«кто нам должен»** — должны прийти цифры из базы.
3. Дальше — готовые сценарии («Утренняя сводка руководителя», «Разбор закрытия месяца», «Акт сверки
   с контрагентом»). В Claude Desktop они в меню **«+» → 1c-odata**, в Cursor и VS Code — через `/`.
   Что ещё спрашивать — [SCENARIOS.md](SCENARIOS.md).

Если в базе несколько организаций, назовите нужную в вопросе («по организации Ромашка»); список —
«какие организации есть в базе».
Несколько баз 1С сразу — [CONNECTING.md](CONNECTING.md#несколько-баз-1с).

## Если не работает

| Что видно | Что сделать |
|---|---|
| Приложение пишет, что не может запустить `npx` (`spawn npx ENOENT`, «Failed to spawn process») | Приложение не видит Node.js. Указать полный путь к `npx` в `command` (`which npx` на macOS, `where npx` на Windows) и перезапустить приложение. На Windows помогает `"command": "cmd", "args": ["/c", "npx", "-y", "1c-odata-mcp"]` |
| Сервер не появился в списке инструментов | Приложение не перезапущено полностью, или в конфиге ошибка (лишняя/недостающая запятая). Проверить JSON и перезапустить |
| 401 / «ошибка авторизации» | Не те логин или пароль — шаг 3, про облачные площадки |
| «Сущность не найдена», пустые ответы | Объект не добавлен в «Состав» OData в 1С — [CONNECTING.md](CONNECTING.md#минимальный-состав-для-этого-сервера-бухгалтерия-30) |
| 404 или адрес не открывается | Нет завершающего `/` в `ODATA_BASE_URL`, или OData не опубликован — [ODATA-SETUP.md](ODATA-SETUP.md) |
| Ответ идёт 15–30 секунд | Нормально для облачных 1С на тяжёлых проверках: облако обрабатывает запросы по очереди |

Полная таблица диагностики — в [CONNECTING.md](CONNECTING.md#таблица-диагностики). Не получилось —
[issue на GitHub](https://github.com/evilbruce666/1c-odata-mcp/issues) с текстом ошибки (без пароля).
