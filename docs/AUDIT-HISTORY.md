# Хронология документов 1С через стандартный OData

Заметка к инструменту `read.audit.get_document_history`: какие источники времени
проверены, что из них можно извлечь и чего извлечь нельзя. Исследование проведено
по `$metadata` живой публикации БП 3.0 (1351 EntitySet, OData 3.0) и ограниченным
GET-пробам по одному документу `Document_РегламентнаяОперация`.

## Три разных понятия

| Поле | Откуда | Что означает |
|---|---|---|
| `documentDate` | `Document.Date` | Учётная дата документа. Не время создания и не время выполнения |
| `refCreatedAt` | `Ref_Key` (UUID версии 1, RFC 4122) | Момент генерации ссылки, UTC. `confidence: "derived"` |
| `executedAt` / `modifiedAt` | — | Через стандартный OData недоступны. В ответе отсутствуют |

## Проверенные источники

| Источник | Результат |
|---|---|
| `Ref_Key` документа | UUIDv1: 60-битная метка времени (100 нс от 1582-10-15Z) + поле node. Единственный найденный источник реального времени |
| `DataVersion` | Непрозрачная версия объекта (8 байт в base64). Метку времени не содержит |
| `Period` записей `AccountingRegister_Хозрасчетный_RecordType` | Учётное время (конец периода), не время записи. Других временных полей у записей нет |
| `InformationRegister_ВерсииОбъектов`, `…НастройкиВерсионированияОбъектов` | В проверенной публикации не опубликованы |
| Журнал регистрации | Стандартным OData не публикуется |
| `ExchangePlan_*` (регистрация изменений) | В проверенной публикации отсутствуют |
| `ДатаСоздания` / `Автор` / `Изменил` | Есть только у справочников файлов, не у документов |
| `Ответственный_Key` | Реквизит «Ответственный». Не доказывает, кто создал/выполнил/изменил документ |

## Ограничения `refCreatedAt`

- Это момент генерации ссылки, а не проверенное время создания, выполнения или
  проведения. Повторная запись или перепроведение документа ссылку не меняют.
- Ссылка могла быть задана программно или перенесена из другой базы (обмен,
  загрузка данных) — тогда метка отражает генерацию в другой базе.
- Корректность часов и часовой пояс генерирующей машины через OData не проверить.
  Инструмент отдаёт UTC как есть; перевод в местное время — задача отчётного слоя.
- Поле node — часть UUID; оно не доказывает, что ссылку сгенерировал конкретный
  физический сервер 1С.
- Для UUID другой версии или варианта метка не возвращается.

## Исследовательское наблюдение (не логика приложения)

На проверенной базе значения `DataVersion`, декодированные как 64-битное число, у
документов, записанных подряд, идут подряд. Это похоже на сквозной счётчик записей
базы, но не доказано, зависит от СУБД и никак не используется инструментом.
`DataVersion` возвращается без изменений и хронологически не интерпретируется.
